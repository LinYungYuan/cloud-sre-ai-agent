RCA WORKER · GOOGLE ADK MULTI-AGENT

Agent 負責分析，Python Tool 守住 MCP 與 Evidence 邊界

Metrics、Trace、Log 都是載入專屬 Skill 的 Google ADK Agent。每個 Agent 只能呼叫自己的 run-scoped Evidence Tools；Tool 完成 MCP 查詢並先提交 evidence，才回傳 bounded chunks。Root RCA Agent 最後只整合通過引用驗證的 observations。

01 · ARCHITECTURE

ADK Multi-Agent 元件架構

橘色代表兩個核心：ADK Specialist Agents 與受控 Evidence Tools。模型不能選擇 endpoint、tool name、scope 或 time window；Root RCA Agent 維持 `tools=[]`。

02 · PROCESS

一次 RCA Job 的完整執行流程

五條泳道分開呈現 deterministic orchestration、ADK Specialist、受控 Tool、持久化與 Root RCA。Evidence 在第 5 步 commit，Agent 才能在第 6 步取得 chunks。

與上一版最大的差異

不是 Collector 先在 Agent 外部收集完所有資料；而是每個 ADK Specialist Agent 主動呼叫自己的受控 Tool。Tool 內部完成 MCP、驗證、大小限制與 evidence commit，再把可分析 chunks 回給原 Agent。

不交給 LLM 的權限

Endpoint、tool name、project、provider、scope、time window、pagination limits、retry 與 mutation policy 全部仍由 deterministic Python code 控制。三個 Specialist 全部完成才可輸出 COMPLETE；部分成功保留 observations 並降級為 PARTIAL；全部失敗則輸出 FAILED。
